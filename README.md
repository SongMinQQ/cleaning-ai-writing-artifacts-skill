# Cleaning AI Writing Artifacts

An Agent Skill for auditing and cleaning AI-assisted documents before final delivery.

This skill is intended for document-oriented tasks such as cover letters, application essays, reports, proposals, and formal summaries. It checks for hidden Unicode artifacts and overly synthetic writing patterns while preserving the original meaning, facts, citations, and author intent.

## Why

AI-assisted writing can sometimes contain artifacts that are undesirable in a final document.

Examples include:

- Invisible Unicode characters such as zero-width spaces
- Unexpected formatting or control characters
- Repetitive transitions and sentence structures
- Generic or overly abstract expressions
- Mechanical patterns commonly found in generated prose

This skill adds a final document-cleanup step without affecting normal coding, debugging, Q&A, or everyday conversations.

## What It Checks

### Hidden Unicode Artifacts

The skill inspects text for suspicious invisible characters including:

- `U+200B` — ZERO WIDTH SPACE
- `U+200C` — ZERO WIDTH NON-JOINER
- `U+200D` — ZERO WIDTH JOINER
- `U+2060` — WORD JOINER
- `U+FEFF` — ZERO WIDTH NO-BREAK SPACE / BOM
- Unexpected bidirectional control characters

Characters are removed only when they are not required for legitimate text semantics.

### Synthetic Writing Patterns

The skill also reviews patterns that can make a document feel unnecessarily machine-generated, such as:

- Repeated transitional phrases
- Excessive parallel sentence structures
- Generic claims without concrete evidence
- Uniform sentence length
- Repeated paragraph structures
- Unnecessary conclusions or restatements
- Inflated or abstract wording

These patterns are treated as editing signals, not as evidence that a document was written by AI.

### Statistical Watermarks

Some AI systems may use provider-specific statistical watermarking techniques based on token-generation patterns.

These cannot reliably be detected or removed through ordinary string processing alone.

Therefore, the skill never claims that a statistical watermark has been detected or removed unless a compatible detector is actually available.

Without such a detector, the status is reported as:

```text
statistical watermark: unknown
```

## When the Skill Should Run

The skill is designed to activate when finalizing user-facing prose documents, including:

- Cover letters
- Application essays
- Reports
- Proposals
- Memos
- Formal summaries
- Long-form documentation

It should not normally run for:

- Programming questions
- Debugging
- Algorithm explanations
- Short Q&A
- Casual conversation
- Raw notes

## Behavior

The cleanup process follows four principles:

1. Preserve the author's intended meaning.
2. Preserve facts, numbers, names, dates, URLs, and citations.
3. Remove unintended hidden text artifacts.
4. Improve unnatural writing patterns only when doing so improves readability.

The skill must never invent personal experiences or factual details just to make writing appear more human.

## Example

Input:

```text
저는 문제를 해결하는 과정에서 사용자 경험과 기술적 완성도를 함께 고려하는 개발자입니다.
단순히 기능을 구현하는 것을 넘어, 문제의 본질을 파악하고 최적의 해결책을 도출하는 것을 중요하게 생각합니다.

또한, 협업 과정에서는 원활한 커뮤니케이션을 바탕으로 팀의 목표를 달성하고자 노력했습니다.
이를 통해 기술적 역량뿐만 아니라 협업 역량도 함께 성장시킬 수 있었습니다.
```

The text may additionally contain invisible Unicode characters that are not visible in the rendered example.

After processing, the skill:

- removes unintended invisible characters,
- reduces repetitive or mechanical expressions,
- preserves the original claims,
- and returns cleaner document prose.

## Installation

Place the skill directory inside the skills directory supported by your agent runtime.

For runtimes supporting the common Agent Skills directory:

```text
~/.agents/skills/cleaning-ai-writing-artifacts/
```

The final structure should look like:

```text
~/.agents/skills/
└── cleaning-ai-writing-artifacts/
    ├── SKILL.md
    └── README.md
```

## Testing

A useful test fixture should contain both:

- known invisible Unicode characters,
- intentionally repetitive AI-like writing patterns.

For example, insert known characters such as `U+200B` or `U+2060` into otherwise normal prose.

Expected audit result:

```text
hidden artifacts: found
statistical watermark: unknown
```

After cleanup, verify that:

- suspicious invisible characters are gone,
- the meaning has not changed,
- factual information is preserved,
- and the resulting prose remains natural.

## Limitations

This project is not an AI-authorship detector.

Writing style alone cannot reliably determine whether text was generated by an AI system.

Likewise, provider-specific statistical watermarking cannot generally be verified from plain text without access to the corresponding detection mechanism.

The goal of this skill is document hygiene and editing quality, not attribution.
